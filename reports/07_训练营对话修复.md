# 训练营对话修复（2026-11-01，用户演示 + 屏幕记录）

用户发现训练营里很多对话没翻。排查用了两路记录：采集模式记下所有未翻译的原文，`scripts/screen_recorder.ps1` 每 3 秒截一张屏（排查结束后已删除）。前后验证了三轮。

## 问题与原因

之前只实测了开场军官那几句，就按它的格式推导了全部对话。实际上岗位 NPC 的格式不同：

| 现象 | 实际原文 | 处理 |
|---|---|---|
| 不补句号 | `" Spread Ammo replenish (1x) all weapon in your inventory "` | 构建时每句对话同时生成带句号、不带句号两个键 |
| 按键两边包冒号 | `" … then press ::HOLD: L2:"`、`"… press ::TAP: ■ :"`、键盘为 `:I:` | 正则里写 `{KEY}`，构建时展开成三种写法，显示为“【长按 L2】”“【点按 ■】”“【I】” |
| 名字后还有标点 | `" … shoot em all up Sarge !!!"`、`" … spent Sarge? well look no more!"` | 每句写“句号版”和“叹号版”两条 `r:` |
| 插入物品名 | `" … revive them with Plastic Gun."` | 专门规则 + 通用兜底 |
| 多句合成一页 | `" use Radio….\n Also use Medal Radar….\n You will need…."` | 通用按行拆分 `sr:`，配置 `MaxTextParserRecursion=5` 允许递归 |
| 长句前面多一个空行 | 译文被加回了行首空格，Unity 在该空格处断行 | 生成带前导空格的键精确命中；拆分规则顺带去掉行首空格 |
| 名牌 `Army Tower Lv.3` 不翻 | `sr:` 拆分在这类名牌上不生效（.NET 下能匹配，原因未查明） | 构建时直接生成“名称 Lv.1～5”词条 |
| `R.T.S` | 地图模式对话下的小标题 | 译为“即时战略（RTS）” |

## 读 XUnity 源码得到的规则（重要）

- **`r:` 和 `sr:` 都是从文件末尾往前试，第一条匹配上就采用，不会回退。** 同一句的通用写法要放前面，特殊写法放后面；兜底规则放文件最前。之前名牌军衔没翻，就是因为通用名牌规则写在后面，被先采用了。
- 词典直接命中（包括采集产生的 `原文=原文` 缓存）优先于所有正则。**采集缓存不清空会挡住正则**，所以每次改规则都要清空游戏里的 `_AutoGeneratedTranslations.txt`。
- 只按去空格的键命中时，XUnity 会把原文首尾的空白加回译文；只有原样键命中时不会加。
- `sr:` 的分组按 `${组名}` 做字符串替换；名字以 `_i` 结尾的组不翻译。
- 加载译文文件时，键会原样保留首尾空格。

## 工具

- `scripts/screen_recorder.ps1`：定时截屏（缩小为 1/3，JPEG），用于回看用户演示。
- `scripts/test_regex.ps1`：用 .NET 按 XUnity 的顺序离线模拟 `r:` 规则，改规则后先跑一遍再进游戏。

## 结果

第三轮验证时，采集日志里已没有训练营对话。用户反馈“基本没有问题”，剩下 HQ 岗位那页多出的一个空行，已按上表修复。**这一处修复后还没进游戏复测。**
