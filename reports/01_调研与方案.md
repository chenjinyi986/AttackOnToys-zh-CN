# Attack on Toys 汉化：调研与方案（2026-11-01）

## 1. 游戏技术画像

| 项 | 结论 |
|---|---|
| Steam AppID | 1269690（depot 1269691，buildid 26265248） |
| 开发商 | N7T-GAMES，抢先体验，官方仅英文 |
| 引擎 | Unity **2019.4.41f2**，**IL2CPP** 后端（`GameAssembly.dll` + `global-metadata.dat` v24） |
| 资源 | 全部场景与资源打包在 `Attack on Toys_Data/data.unity3d`（UnityFS，约 1 GB，116 个内部文件，56 个场景） |
| UI | 旧版 UGUI `UnityEngine.UI.Text`（28,797 个组件）。工程里有 TextMeshPro 程序集，但**场景中没有使用** |
| 字体 | `ArialBold`（内嵌 TTF，用于约 73% 的 Text）、`gunplay rg`（标题装饰字体）、Unity 内置 `Arial` |
| 内置本地化 | **没有**，游戏里没有任何语言切换或本地化表 |
| 网络 | Unity 旧 HLAPI（UNET），用于局域网 PvP |

## 2. 创意工坊机制（关键结论）

游戏本身支持创意工坊，但只识别两类内容：

1. **Toy-Box 关卡**：`.toybox` 存档文件，由游戏内编辑器上传。
2. **Mod**：用游戏提供的 Unity 工程 + `AOTModBakerEditor` 打包的 AssetBundle，内容是兵种、道具、天空盒、主角模型等**预制体**，加载后插入游戏列表。

IL2CPP 构建的 AssetBundle 不能携带新代码，游戏也不会从工坊读取任何文本或字体。所以**订阅一个工坊物品不可能让游戏自动变成中文**。
工坊在这里只能做**分发渠道**：玩家订阅 → Steam 自动下载到 `steamapps/workshop/content/1269690/<物品ID>/` → 首次运行一次安装脚本。

## 3. 文本分布

| 来源 | 数量 | 说明 | 文件 |
|---|---|---|---|
| 场景/预制体里的 UI.Text 静态文本 | 339 条（去重） | 菜单、按钮、提示 | `translation/source/ui_texts.json` |
| 游戏脚本组件的字符串字段 | 5,768 条（启发式，含大量内部名） | 道具/兵种名、设置项、任务简报、**教程对话碎片**（运行时拼接） | `translation/source/data_strings.json` |
| 代码硬编码字面量 | 7,787 条（大部分是 .NET/Unity 系统字符串） | 如 `HQ IS DESTROYED`、`NEXT WAVE   ` + 计时 | `translation/source/code_strings.json` |

大量 Text 组件的内容由代码在运行时赋值或拼接（例如教程对话 `"Press " + 按键 + " to jump"`）。这类文本在资源里是碎片，只有在运行时才能看到完整句子。

## 4. 方案对比

### 方案 A（推荐）：BepInEx 6 IL2CPP + XUnity.AutoTranslator，工坊分发

- 运行时挂钩所有 `Text.text` 赋值，按我们提供的译文表替换（**关闭机翻**，只用人工校对过的译文）。
- 拼接文本用正则/切分规则处理（XUnity 原生支持）。
- 字体：用 XUnity `OverrideFont` 指定系统中文字体（如微软雅黑），或打一个自定义字体包。
- 译文表可以直接放在工坊目录里由 XUnity 读取，**更新工坊物品即可推送新译文**，玩家无需重新安装。
- 游戏更新后通常仍可用（只要文本没改）。
- 代价：玩家需首次运行安装脚本，把 BepInEx 加载器复制进游戏根目录；BepInEx IL2CPP 第一次启动要生成互操作程序集（约 1～3 分钟），且默认会从 `unity.bepinex.dev` 下载 Unity 基础库（国内网络可能慢，可预置在包里规避）。
- 版本：BepInEx 6.0.0-be.791（2026-10-23）、XUnity.AutoTranslator 5.6.3.1（BepInEx-IL2CPP 版）。

### 方案 B：直接修改 `data.unity3d` 与 `global-metadata.dat`

- 静态 UI 文本可以精确替换；但脚本组件字段没有 TypeTree，只能按字节猜位置改，风险高。
- 运行时拼接的句子无法完整翻译。
- 要分发约 1 GB 的修改文件或差分补丁，游戏每次更新都会失效，并会被 Steam 校验覆盖。
- 结论：不适合本游戏。

## 5. 工坊上架形态（方案 A）

```
<工坊物品>/
├─ 安装汉化.bat / 卸载汉化.bat   # 定位 ..\..\..\common\Attack on Toys，复制/删除加载器
├─ payload/                       # BepInEx 6 IL2CPP + XUnity.AutoTranslator + 预设配置
├─ Translation/zh-CN/Text/*.txt   # 译文表，XUnity 直接从工坊目录读取 → 随工坊自动更新
├─ README.txt
└─ preview.png                    # 工坊封面
```

上传方式：用游戏自带的 `steam_api64.dll` 写一个小上传器（Steam 客户端已登录即可，不需要输入密码），或由用户本人运行 SteamCMD `workshop_build_item`。
首次上传设为**私有**，确认游戏内工坊浏览器不会把它当关卡/Mod 加载出错后再公开。

## 6. 风险与待验证

- 游戏内工坊列表会读取已订阅物品：需验证非关卡/非 Mod 物品不会导致游戏报错（用私有物品实测）。
- BepInEx 与 UNET 局域网联机的兼容性需实测（理论上无影响，联机双方都应安装汉化以避免显示差异，但不影响同步）。
- 旧版 UGUI 动态字体在缺字时的表现，以及 `Gunplay` 标题字体替换后的观感，需要截图确认。
- 工坊发布物中包含第三方 DLL（BepInEx LGPL-2.1、XUnity MIT），需附带许可证文本。
