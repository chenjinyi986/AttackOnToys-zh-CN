## 结果

- **加载正常**。首次启动约 1 分钟：下载 Unity 基础库（5 MB，`unity.bepinex.dev`）→ Cpp2IL（3 秒）→ 生成 interop（25 MB）。之后启动几乎无额外耗时。
- **中文显示正常，不需要字体包**。旧版 UGUI 动态字体缺字时会回退到 Windows 系统字体（雅黑类），清晰可读。缺点：原英文按钮是 ArialBold，中文回退字体偏细。可选优化：`OverrideFont` 或给标题单独指定粗体。
- **运行时采集可用**：用 `CustomTranslate` 指向本地回显服务 `scripts/capture_server.py`，浏览一轮主菜单、设置、任务选择就拿到 426 条文本（`translation/source/runtime_texts.json`）。

## 发现的问题

| 问题 | 影响 | 处理 |
|---|---|---|
| 游戏关闭了旧版输入系统（`disableOldInputManagerSupport=True`） | XUnity 热键（Alt+R 重载、Alt+T 切换）全部无效 | 开发时改译文需重启游戏；对玩家反而避免误触 |
| IL2CPP 裁剪了 `WaitForSeconds(float)` 构造函数 | XUnity 的防抖协程报 `MissingMethodException`（影响自动写文件的节流） | 发布模式不写文件，可忽略 |
| `Text.set_text` 内部偶发 `NullReferenceException`（游戏自身问题，在 `Graphic.SetVerticesDirty` 中） | 钩子会把异常吞掉而不是抛回游戏，理论上改变了异常后的执行流程 | 目前没看到功能异常；进关卡后要重点观察 |
| `TextMesh`、`UIElements`、`WWW` 类型被裁剪 | 仅启动时警告 | 发布配置里关闭 `EnableTextMesh` |
| BepInEx 控制台窗口会弹出并抢焦点 | 体验差 | `config/BepInEx.cfg` 已设 `[Logging.Console] Enabled = false` |

## 文本形态要点

- 游戏会把数据里的文本转成**大写**再显示（数据 `Music Volume` → 屏幕 `MUSIC VOLUME`）。译文表的键必须是屏幕上的实际形式，所以以运行时采集为准，静态提取的文本要同时生成大写版本。
- 有拼接文本：`COLLECTIBLE MEDAL 0 / 5`、`:TAP: BUTTON A`、`R /  T` 等，需要用 XUnity 的 `r:` / `sr:` 正则规则。
- 纯数字和符号不会送翻译（XUnity 判定为不可译）。

## 配置文件

- `config/AutoTranslatorConfig.capture.ini`：开发采集模式（不可分发）
- `config/AutoTranslatorConfig.release.ini`：发布模式（`Endpoint=` 为空，只读人工译文）
- `config/BepInEx.cfg`：关闭控制台

游戏目录当前处于**发布模式配置**，加载器保持安装状态，随时可以继续开发。
